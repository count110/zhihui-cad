## 5. 已知问题与风险

- 公差表、机械标准表是手工录入或按公式计算的，已和若干已知值核对，**使用前应对照现行国标**；表里查不到的值系统会反问，不会编造。
- 三维“隐藏线/着色”用画家算法，复杂遮挡可能不准。
- 视口内冻结图层写入 DXF 是尽力而为，在 AutoCAD 里的显示未实测。
- 离线规则 Planner 只覆盖演示口令和常见变体（36/50 条基准），只给测试用；产品里所有口令都由大模型规划，实测成功率见第 11 节（每次结果有波动，同一条用例可能这次过、下次不过）。
- 工具函数返回的 `defaults_used`（“文字高度使用默认值 3.5”等）会出现在完成消息的“说明”里；样式类参数使用默认值是允许的，但**关键数值（半径、长宽、高度、公差值、粗糙度值）从不使用默认值，缺了就反问**。

## 6. 这轮测试顺带挖出并修掉的缺陷

写测试和基准的过程中发现、已修复并加了回归测试的真实问题：

1. 导出带外部参照的 DXF 抛 `AttributeError`（`ezdxf.xref` 没导入）。
2. 第三方 DXF 常见的 `Defpoints` 图层让再导出崩溃（重复建层）。
3. 损坏的 DXF 打开时报 `INTERNAL` 而不是明确的“文件无法解析”。
4. 图形界限根本没写进 DXF（ezdxf 保存时用模型空间 LAYOUT 的界限覆盖表头）。
5. 第三方 DXF 的标注导入后再导出整个丢失；布局和视口比例没读入。
6. 修剪后图元编号变了（应改原对象）。
7. 识别器：“椭圆”被其中的“圆”字误判成圆；“和 L3 相交的…”类关系短语抛 `IndexError`；“红色的线”不认随层颜色；“左上角的小圆”被当成角点；“第一个”只认阿拉伯数字；“它”在选中多个时取第一个。
8. 路径扫掠体的体积只有真实值的 1/3（端面三角形朝向不一致）。
9. 动态块查询参数：传名字列表直接崩溃；查询带出的参数值被旧值挡住。
10. 渐变填充的颜色（`#RRGGBB`）写 DXF 时被拆成单个字符。
11. 全是“安静”函数的批量也产生了新版本；“新建一张图，导出成 DXF”缺 `drawing_id`；“新建图层辅助线”被当成“新建图”。
12. 口语规范化把“三维”的“三”转成数字；“直径40的源”的“源”没纠正为“圆”。
13. 离线规则 Planner 不会处理“从 A 画到 B 再画到 C”“在原点画一个圆”“写文字…，字高5”“画 M8 螺栓，长30，在…”（逗号切句后补充参数丢失）。

## 8. 追加：任意体三维布尔（manifold3d，2026-10-20）

你同意把 `manifold3d` 作为**可选依赖**引入后做的：

- **做法**：两个 z 向棱柱仍走精确的 slab 路径（不需要依赖）；其它情况用 manifold3d：棱柱按层挤出再求并（避开阶梯面的 T 形接缝），其它实体用网格（先检查封闭性并统一朝向）。结果是普通网格（`solid_kind="boolean"`），可继续移动/旋转/阵列/再布尔/撤销重做/导出 STL 与 DXF MESH/渲染。没装依赖：明确报 `BOOLEAN_UNSUPPORTED` 并提示 `pip install manifold3d`，图纸不被修改。依赖声明在 `pyproject.toml` 的 `optional-dependencies.solid`。
- **顺带修的缺陷**：旋转角小于 360° 的旋转体端盖朝向写反、网格不封闭；现在拉伸/锥度/旋转/扫掠的网格都封闭且法线朝外。
- **审查与验证**：我用 4 路独立审查（数值稳健性、与其他功能的衔接、没装依赖与文档、差分/属性测试）。**第一次审查因会话额度用尽全部失败，没有任何结论；第二次也在中途停摆，只留下部分结论**，所以没有把它当作“通过”。留下的结论里有 3 个真实问题，已修并加了回归测试：
  1. **我自己引入的回归**：统一朝向时把内腔壳（体积为负）整块翻成朝外，导致带孔截面旋转 360° 的体积变成“外形 + 孔”（219284，应为 156631），含封闭空腔的布尔结果再参与运算也会算错。现在按嵌套深度决定每个壳的朝向（实体壳朝外、内腔壳朝内）。
  2. 一个旧的几何内核测试写死了“没装 manifold3d”，装了依赖就失败；改成模拟没装。
  3. “空结果”用绝对阈值（1e-9），边长 0.001 的实体会被误报为空；改成相对阈值。
  其余审查项（变换/阵列/导出/渲染/撤销重做/尺度 1e-3…1e5/远离原点/链式布尔）审查员记录为通过；我另外补了 60 对随机棱柱的 slab 路径与网格路径差分测试（体积一致）、没装依赖的真实降级检查、72 段圆连续 6 次布尔 0.17 s 的性能检查。
- **没验证到的**：审查员没来得及完成“文档措辞是否过时”一项，我自己 grep 了所有文档和工具说明并改过；数值稳健性只覆盖了审查员实际跑过的那些情形。
- **已知限制**：① 两个实体只是共面“擦边接触”时，manifold3d 可能输出零厚度的碎片（体积、封闭性正确，包围盒/渲染线条可能偏大），已丢弃独立的零体积碎片，但依附在主体上的碎片无法可靠去除；② 三维实体不能用点选/栅栏/穿过边的交叉窗选中（窗选正常），这是原有限制，不是布尔引入的。
- **部署**：新的 runtime 里需要装 manifold3d（见部署记录）。

**失败原因分析和修复**（逐条用 `--verbose` 看模型给出的计划；`--verbose` 现在会打印计划参数、识别结果和每步工具结果）：

- **最大的原因是关键词路由把工具子集卡死了**：路由按关键词选 1–3 个类别，只把这些类别的函数给模型；“剪掉”“刷成”“拖到”“三维建模空间”这类说法被分到没有对应函数的类别，模型只能编函数名（连续 3 次格式不合格）或者用错的函数凑（如用撤销+重画代替夹点拖动）。改为：路由关键词补全；模型写了子集外的函数名时，重来一次并换成全部函数的目录；模型在计划里声明的类别超出子集时，并进子集再请求一次（只放宽不缩小）。
- **代码缺陷**：`select_entities` 的 `filter_criteria` 原样传给 `select.query`，模型写 `type` 之类的键就抛 `TypeError`（报成“内部错误”）。现在先认常见别名，不认识的键报 `BAD_ARGS` 并列出可用条件。
- **模型看不到嵌套参数的字段名**：工具目录里 `parameters_and_actions` 显示成“任意”，`spec_params` 显示成“对象”，模型只能猜字段名（动态块、标准件反复 INVALID_ARGS）。现在目录展开嵌套模型的字段，专业工具集在目录行后列出各生成器 `spec_params` 的必填键（从代码里的表生成，不手抄）。
- **静默的无效操作**：动态块的线性拉伸参数不写 `geometry_refs` 时什么都不拉伸，参数等于摆设。现在明确报错并在提示里列出块内图元编号。
- **提示词自身的错误**：第一个 few-shot 给“板上带孔”填充用了 `island_style: "outer"`，模型照学。改成 `normal`；并补了四条规则（轮廓里的封闭图形默认当孔/岛、识别 query 只写外轮廓；工作空间切换用 `manage_workspace_ui`；“拖某个点”是夹点编辑；“一次做完”放进同一个批量）。
- **其它**：`#FF0000` 这类正好等于 ACI 1–6 的 RGB 写法按 ACI 存（模型常这么写“红色”）；“矩形的左下方顶点”识别为角点而不是“左下方的图元”。
- **口语规范化的数值错误**（审查化工设备图任务书时发现）：阿拉伯数字后面的“千/百/万”被当成独立的中文数字，“600千帕”变成“6000帕”、“15千瓦”变成“150瓦”、“1千”变成“10”，错的数还会被数值护栏当成用户给的数放行。现在阿拉伯数字后的这些字保持原样，纯中文数字照常转换。

**基准检查器和用例的调整（如实说明，避免把放宽说成提升）**：
- 检查器原来在真实模式下只认计划顶层和工具结果事件里的函数名，模型把函数放进 `cad_batch_execute` 时会被误判为“没调用”——修复前的 18 条失败里至少 3 条是这个原因（A003、A007、B008，重跑确认函数其实在批量里；A004 可能也是，重跑时模型没用批量，无法确认）。计划事件现在带上参数，检查器能看到批量里的函数。
- 真实模式下：只读的感知函数不再强求（模型可以直接用上下文里的信息，结果由状态断言检查）；取捕捉点用 `resolve_osnap_point`、`get_entity_snap_points` 或识别步骤都算；步骤结果断言在步骤号对不上时在所有步骤结果里找；约束断言不计顺序。
- 改了 7 条用例：A005（口令没给样式名，改为检查样式参数而不是名字）、A011（口令里带上预置文件的 file_ref，原口令“另一张图”没说是哪个文件，模型反问是对的）、A013/A016/A020（口令缺了断言要求的信息：孔、标注对象、直径标注和圆心）、A021（负半径：脚本模式整批回滚失败；真实模式反问半径也算对，但不能留下半截图形）、D007（改用“结果里出现圆心坐标”断言）。规则 Planner 同步支持“给矩形加平行度…”这种带对象的说法。
