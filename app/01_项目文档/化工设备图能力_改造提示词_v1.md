## 第一部分　给开发 Agent 的总指令

### 0. 背景：现状和要改成什么

**根因（按影响排序，开发时逐条消除）**：

1. **没有“设备图”这个图种**。`Drawing.mode` 只有 `Literal["pfd","general"]`（`zhihui/ir/models.py:299`）；流程图第二级路由 `RouterOutput.kind` 只有 `pfd | water_elevation`（`zhihui/agent/coord/roles.py:13-17`）。所以设备图口令不会被判为“不支持”，而是被当成“新建流程图”。
2. **路由把设备名当成流程图信号**。`PFD_WORDS`（`zhihui/agent/general/router.py:11`）里有“储罐/反应釜/换热/精馏/填料塔…”；两套词表里都没有“设备图/装配图/管口方位/封头/筒体/鞍座/人孔/壁厚/设计压力/管口表”这类设备图信号。另外有误命中：“固定管板”里的“固定”命中约束类，“20块塔板”里的“块”命中块类（`CATEGORY_RULES`）。在已打开的通用图里，`route(p,"general")` 对“储罐的进料管道改成DN100”这类改设备的口令也会返回 pfd。
3. **没有设备领域模型**。流程图里的 `Equipment`（`models.py:83-95`）只是“位号 + 固定比例图例”，`params` 是自由文本、不参与几何；61 个图例（`zhihui/cad/symbols/*.json`）的大小和真实设备无关（`symbols.py:39` 统一放大 1.25 倍）。
4. **通用 CAD 会主动把化工请求转走**。`invoke_engineering_toolset(domain="chem"|"water")` 不画图，而是新建流程图并返回 `switch_to`（`zhihui/tools/general/spec_tools.py:236-250`）；`zhihui/cad/toolsets/__init__.py` 的 `DOMAIN_TOOLS` 里只有机械和建筑。
5. **用基础图元“手拼”设备注定失败**。设备图上几乎每个坐标都是参数之和（例如封头顶 = 筒体高 + 直边 + 曲面高），模型一写出这类数就会被数值护栏拦下（`zhihui/agent/general/guards.py:39-46` `_allowed()`，报 `E_UNSOURCED_VALUE / E_HARDCODED_COORD`），重规划 2 次后失败（`engine.py` 的 `MAX_REPLAN=2`）。这和“模型不算坐标”的硬约束一致，所以**正确做法是把设备几何做成确定性生成器：模型只给参数，一次调用画出全图**。用现有函数按脚本手工拼一台储罐（约 45 次调用：直线、椭圆弧、修剪、法兰生成器、填充、标注）是拼得出来的，说明底座够用，缺的是领域层。
6. **没有标准尺寸数据**。仓库里没有封头、管法兰、人孔、支座等标准件的尺寸表；`01_项目文档/标准资料/` 里也没有任何压力容器或设备设计标准的原文。

**目标**：把产品改成**化工设计专用绘图工具**，一个入口，覆盖三类化工图：

| 图种 | 现状 | 本次 |
|---|---|---|
| 工艺流程图（方案/物料/施工流程图）、给水高程图 | 已有（pfd 模式） | 保留，只改路由和入口文案 |
| **化工设备图**（设备装配图/总图 + 管口方位图） | 没有 | **新增，本次重点** |
| 零部件图（封头、法兰等） | 没有 | P2 |

通用二维/三维 CAD 不再作为单独的卖点：它是设备图的绘制引擎，同时留给用户做补充编辑（加注释、改线、补局部视图等）。

**P0 输出的定位是“方案图/条件图”，不是施工图。** 标题栏图名后加“（方案图）”；技术要求最后一条固定写“本图未进行强度计算、开孔补强计算和支座校核，不得直接用于制造”。补强圈、质量计算、焊缝符号、支座校核放到 P1 及以后。

**成功判据**（第 10 节把它们写成可执行的断言；“上图字段”指 Di、δ、筒体长度或切线长、DN、设计压力、设计温度，比较前统一用 `fmt_value()` 格式化）：

| 用例类型 | 算成功的条件 |
|---|---|
| ① 新建 | 状态 READY 或 READY_WITH_WARNINGS；`equip_check` 0 个错误；视图包含主视图和管口方位图（卧式为左视图）；表格包含设计数据表、管口表、明细栏、标题栏；来源为 `user:*` 的每个值都能在本轮口令里找到（`equip_values_from_user`）；新增版本数 = 1 |
| ② 缺参数 | 状态 WAITING_CONFIRMATION；反问的待问路径覆盖期望路径（`clarify_covers`）；新增版本数 = 0 |
| ③ 改图 | 目标路径等于期望值，且来源为 user；其余 user 字段不变；0 个错误；新增版本数 = 1 |
| ④ 路由 | 路由结果等于期望；期望 pfd 时不生成设备参数 |
| ⑤ 错误输入 | 出现期望的错误码；新增版本数 = 0 |
| ⑥ 导出 | 产出 DXF 和 PDF，并且 PDF 是从布局「设备图」渲染出来的 |

**成功率** = 通过的（用例 × 口令写法）数 / 运行数，用 `--llm real --no-asr --category E` 统计。P0 至少跑两轮，取最低值；语音误识别写法单独报告。报告里写明模型名、temperature 和日期。**目标**：P0 结束时 E 类口令写法成功率 ≥ 80%（取两轮中的最低值）；第 11 节 P0 的演示口令全部能演示。

### 1. 硬性约束（违反任何一条都算失败）

1. **现有能力零回退**：现有 `pytest`（约 950 个）全部通过；`python -m zhihui.bench.run`（scripted）现有 G/M/F/C/S 和 B/D/A 类结果不能变差。每个阶段结束都要跑一遍。
2. **几何确定性**：设备的部件几何、视图、管口方位、尺寸、件号、表格排版，全部由 `zhihui/cad/equipment/` 里的确定性函数完成（可以调用 `zhihui/cad/geom/` 的原语），每个函数都要有单元测试。**大模型不算任何坐标、尺寸链、总高、方位角换算、单位换算，也不猜图元编号或管口符号。**
3. **标准尺寸只能来自带出处的数据表**：标准件尺寸一律从 `zhihui/cad/equipment/data/*.json` 查表（格式见 5.3 节），表里每一行都带 `source` 和 `verified`。**模型记忆里的标准值不能直接写进代码或数据表，除非标上“未核对”**。查不到的规格不插值、不外推：要么反问用户给尺寸，要么明确报 `STD_SIZE_NOT_FOUND`。用到未核对数据时，图上和回复里都要注明。
4. **不编造数值**：设备参数补丁用专用护栏（9.3 节）。用户没给的**必问字段**（4.2 节）必须反问，而且**一次问完**：一个问题，多个待问项，每项附 2–4 个推荐选项。**可默认字段**由代码里有编号的规则填（不由模型填），回复和图上都要标“按默认”。
5. **安全相关的东西不能装作已校核**：PN、法兰型式、人孔和支座型号这类会影响安全的标准件等级，只在设计条件齐全时才按规则初选，并注明“初选，待校核”；设计条件不全时一律写“待定”。壁厚估算（P1）只能标“参考值，不替代 SW6 等压力容器计算软件”，不得自动写进图。
6. **沿用工程约定**：工具成功返回 `{"ok": true, ...}`，失败用 `ToolError(code, message, hint)`；修改走 `ToolService._mutate` 事务，**一次成功修改只落一个版本**；函数用 `zhihui/tools/general/registry.py` 的 `@tool` 装饰器和 `Args` 注册。**新 IR 里的所有嵌套模型都要设 `extra="forbid"`**（`Args` 的 forbid 只管顶层，嵌套模型默认会静默丢弃写错的字段）。
7. **密钥隔离**：调用大模型的代码只能放在 `zhihui/agent/` 下；MCP 子进程和 ToolService 里只有确定性代码。
8. **依赖**：不新增必需依赖；**新增任何第三方依赖（包括可选依赖）之前，先停下来问用户**。
9. **对输出形态诚实**：导出的 DXF 只经过 ezdxf 自检、没在 AutoCAD/浩辰/中望里打开过的，交付文档里必须写明；简化画法和等价实现都写进功能对照表；不能拿占位实现冒充完成。
10. **旧数据兼容**：IR 只增不改，旧流程图和旧通用图的 JSON 要能无损加载；新字段名加进 `models.py:233` 的 `_NEW_DRAWING_FIELDS`，默认值不写进旧图的 DXF 内嵌 IR。

## 第二部分　工程实现规格

### 3. 总体方案

**设备图 = 通用 CAD 图纸 + 一份容器参数（`VesselSpec`）。** 参数是唯一的真源，图由确定性生成器从参数生成：

```
口述 ──Planner（大模型）──▶ 参数补丁 VesselPatchIn（只含用户说的值）──设备补丁护栏──▶ vessel_define
                                                                         │ 合并进 VesselSpec，按字段记来源（user:<轮次>/rule/table/calc/pfd）
                                                                         │ 默认规则补齐可默认字段
                                                                         │ 缺必问字段 → SPEC_INCOMPLETE → 引擎直接转反问（不画图、不落版本）
                                                                         ▼
                         zhihui/cad/equipment/（确定性）：查标准表 → 部件 → 视图 → 尺寸 → 件号 → 表格 → 布局
                                                                         ▼
                         模型空间 1:1 的通用 CAD 图元 + 布局「设备图」（图框、标题栏、视口、表格、技术要求）
                                                                         ▼
                         导出：PNG/PDF 从布局渲染；DXF 含模型空间和布局；设备图自检
```

1. 图纸仍然是 `mode="general"`，这样现有的编辑、导出、渲染、选择、撤销都能直接用。新增字段 **`Drawing.vessel: VesselSpec | None = None`**。不能叫 `equipment`，因为 `models.py:257` 的 `Drawing.equipment` 是流程图的设备列表，代码里约有 150 处引用；类名也不能用 `EquipmentSpec`，因为 `coord/spec.py:19` 已经占用了。把 `"vessel"` 加进 `_NEW_DRAWING_FIELDS`。前端看到 `mode=="general" && vessel != null` 时进入“化工设备图”工作空间。**不要**新增第三种 `mode`：现有代码里有很多 `d.mode == "general"` 分支（例如 `tools/core.py` 1172–1175、1214–1217 的校验和导出分流）。
2. **生成器图元用确定性编号**：`EQ-<视图>-<部件>-<序号>`，同一份参数重新生成时编号不变。重新生成时按编号做差量：几何没变的不动，变了的更新，消失的删除。生成器图元带标签 `equip:auto`、`equip_part:<部件>`、`equip_view:<视图>`，**不进 `recent_entities`**（否则“刚才那条线”这类指代会被几百个生成图元挤掉）。写图纸空间图元时，先临时把 `d.active_space` 设成布局名，写完再恢复（`Ctx.add` 会强制写进当前空间）。
3. **改图一律改参数再重新生成**（“把进料口转到 90°”“筒体加长 500”），不直接改几何；补丁和重新生成放在同一个 `_mutate` 事务里，只落一个版本。在 `registry.execute` 末尾加一个钩子：通用编辑函数改动或删除了 `equip:auto` 图元时，把它改标为 `equip:detached`，并在结果里警告“此图元已脱离参数，重新生成不会再覆盖它”。用户手工加的图元（没有 `equip:auto`）在重新生成时原样保留。
4. `vessel_define(op=create)` 发现当前图里已有非生成器图元，或者已有 `vessel` 时，报 `CONFIRM_REQUIRED`，不覆盖。

### 4. 数据模型（新文件 `zhihui/ir/vessel.py`；`Drawing` 只加一个字段）

#### 4.1 存储模型（pydantic v2；单位：mm、MPa（表压，允许负值表示真空）、℃、kg、m³；**所有模型 `model_config = ConfigDict(extra="forbid")`**）

```python
VesselKind = Literal["vertical_vessel", "horizontal_vessel",            # P0
                     "hx_fixed_tubesheet", "stirred_reactor_jacketed",  # P1
```

#### 4.2 字段分级（设计说明、Planner 提示词、护栏、反问逻辑都以这张表为准）

| 分级 | 字段 | 缺了怎么办 |
|---|---|---|
| **必问** | `kind`；`shell.inner_diameter_mm`；`shell.length_mm` 或 `shell.tangent_length_mm`；`shell.thickness_mm`；FLAT/CONE 封头厚度；立式容器 `supports[].kind`；支腿/裙座 `height_mm`；每个管口的 `dn`；用户一个管口都没说时问“有哪些管口（用途和 DN）”；用户只说“高/长/高度”而没说是筒体高还是切线长时，问口径 | 不画图。`vessel_define` 报 `SPEC_INCOMPLETE`，hint 里带结构化的 `pending`（路径、中文名、2–4 个推荐选项）。**引擎直接转成反问**（mock 和 real 都一样，问题文字由代码根据 pending 拼出），不再让模型重规划 |
| **可默认（代码规则）** | 封头型式；EHA/HHA/THA/SDH 封头厚度；直边高度；管口位置、方位、伸出长度；接管系列、外径、壁厚；耳座高度位置（R-SUP-POS-02）；支座数量、方位、鞍座位置；出图幅面和比例；管口符号 | 由 4.3 节的规则填，`sources` 记 `rule:<id>`；回复（由引擎根据 `defaults_used` 生成，不让模型自己写）和图上（管口表备注、技术要求）都要注明“按默认，待确认” |
| **设计条件齐全才初选** | PN、法兰标准/型式/密封面、人孔标准与型号、支座型号 | 设计压力和设计温度都给了，才按规则**初选**并注明“初选，待校核”；缺任何一项就写“待定”，并给警告 `W_DESIGN_DATA_MISSING`，**不能取下限出图** |
| **只照抄，缺了写“待填”** | `design.*`、各部件材料、位号、名称 | 照常出图，表格里对应格子写“待填”，状态为 READY_WITH_WARNINGS |

#### 4.3 默认规则（`zhihui/cad/equipment/rules.py`：每条规则有编号、有单元测试；规则里用到的经验数值放进 `data/rules.json`，标 `source` 和 `verified`）

**计算顺序**：R-MARK-01 → R-HEAD-* → R-LEN-01 → 支座（R-SUP-*）→ 管口位置（R-NOZ-LOC/POS）→ 管口方位（R-NOZ-ORI-01，避开已定的支座）→ 伸出长度 → PN/法兰/人孔 → R-STD-01 → R-SHEET-01。管口避让支座，支座不反过来避让管口。

| 编号 | 规则 |
|---|---|
| R-MARK-01 | 管口符号由代码分配：首次生成时，按主视图左下方起顺时针的顺序编 a、b、c…；同规格同用途的用 b1、b2；人孔按 HG/T 20668 习惯（开发前核对原文）。`drawing.mark_style` 可以改为 N1、N2。**分配后保持稳定**：加删管口不重排已有符号，只有用户明确说“重新编号”才重排 |
| R-HEAD-01 | 封头缺省为 EHA（标准椭圆封头，内曲面深度 = Di/4）；立式配 top+bottom，卧式配 left+right |
| R-HEAD-02 | 仅当封头为 EHA/HHA/THA/SDH 时，封头名义厚度缺省同筒体，回复和图上注明“封头厚度按筒体厚度画，未计成形减薄与强度”；FLAT/CONE 的厚度必问 |
| R-MAT-01 | 用户只给一个材料时，只用于受压壳体（筒体和封头）以及 `design.main_material`；接管、法兰、人孔、支座、垫板的材料写“待填”，除非用户分别指定；明细栏不能把板材牌号写到锻件或钢管件上 |
| R-LEN-01 | `tangent_length_mm` → 筒体长度 = 切线长 − 两个封头的直边高度；`length_mm` 与 `tangent_length_mm` 同时给且矛盾时报 `SPEC_CONFLICT`；换算记为 `calc:R-LEN-01`。“总高/总长”作为输入放到 P1 |
| R-ORI-01 | 方位约定（可由 `drawing.orientation_convention` 修改，约定文字写在方位图旁边）：**立式**在俯视方位图上 0° 朝图纸上方，顺时针为正；**卧式**的管口周向角从左封头端向右看（左视图）定义，0° 为正上方，顺时针为正 |
| R-NOZ-LOC-01（立式） | 进料、放空、安全阀、压力表 → `top_head`；出料、排净 → `bottom_head`；人孔、液位计、温度计 → `shell` |
| R-NOZ-LOC-02（卧式） | 进料、放空、安全阀、压力表、人孔 → `shell`，周向在筒体顶部；出料、排净 → `shell`，周向在底部；液位计 → 筒体侧面 |
| R-NOZ-POS-01 | 筒体管口的轴向位置：人孔、液位计按 `rules.json` 的经验位置；其余在筒体可用段内均布；开孔边缘离环焊缝的最小距离取 `rules.json`（以 HG/T 20583 原文核对） |
| R-NOZ-POS-02 | 封头管口按方位均布，约束是开孔（P0 用 `rules.json` 估算的补强圈外径）的外边缘距封头中心 ≤ 0.4Di（出自 GB/T 150.3-2024 的补强适用区，条款号和数值待核对）；出料和排净同时存在时，排净偏心布置；放不下报 `NOZZLE_NO_ROOM` |
| R-NOZ-ORI-01 | 从可用方位里以 45° 为步长，找不与其他管口和支座冲突的位置；`kind=level_gauge` 的一对管口共用同一方位角、上下对齐，中心距用用户给的值，没给就按 `rules.json` 的液位计规格取，并注明“待仪表专业确认” |
| R-NOZ-PROJ-01 | 伸出长度按 DN 分档取 `rules.json` 的经验值，有保温时加上 `insulation_thickness_mm` |
| R-PIPE-01 | 接管外径按 `pipe_series`（项目级，第 14 节）和 DN 查 `data/pipe_dims.json`；壁厚取表里的常用值，`verified:false`，管口表备注写“接管壁厚按默认，未校核” |
| R-PN-01 | **只有用户同时给了设计压力和设计温度才生效**：查 `data/flange_pt_rating.json`（HG/T 20592 压力-温度额定值，按法兰材料组；`verified` 规则同 5.3 节），取设计温度下最大允许工作压力 ≥ 设计压力（底部管口另加液柱静压）的最小 PN，且不低于 `rules.json` 的下限；否则写“待定” |
| R-FLG-01 | 法兰：标准缺省 HG/T 20592，型式和密封面按 PN、DN 分档取 `rules.json`；`medium_property` 含极度/高度危害或易燃易爆时不选 PL 型（以原文为准，待核对）；设计条件不全时写“待定” |
| R-MH-01 | 人孔：设计压力 < 0.1 MPa 时可选常压人孔（HG/T 21515 是常压人孔，待核对）；≥ 0.1 MPa 时**不得**选常压人孔，按 PN 在 HG/T 21514~21535 的法兰人孔里选；人孔 DN 必须由用户给出 |
| R-SUP-01 | 支座数量：卧式鞍座 2 个（固定 F、活动 S 各一）；耳座按 DN 分档取 `rules.json`（常见 3 或 4 个） |
| R-SUP-02 | 支座型号 P0 只做初选（按 DN 查表），明细栏备注写“型号待按 NB/T 47065.x 校核（需要操作/充水质量和风、地震载荷）”，并给警告 `W_SUPPORT_NOT_CHECKED`；鞍座同时注明 A/B 型和包角为默认值，未按 NB/T 47042 校核。P1 有了质量计算后再按允许载荷选型 |
| R-SUP-POS-01 | 鞍座位置：距封头切线的距离 A 按 `rules.json` 的规则取（常用 A ≤ 0.2L，且尽量 ≤ 0.5Rm，出自 NB/T 47042，待核对） |
| R-SUP-POS-02 | 耳座：方位从 45° 起均布（先于管口确定）；高度位置缺省时，耳座支承面距下环焊缝取 `rules.json` 的 `lug_elevation` 经验值（`verified:false`），`sources` 记 `rule:R-SUP-POS-02`，定位尺寸旁注“按默认，待确认（需结合设备重心和支承梁标高）” |
| R-STD-01 | **只有用户给了设计压力才生效**：p ≥ 0.1 MPa 或 p ≤ −0.02 MPa（真空/外压）→ GB/T 150.1~150.4-2024，技术要求同时写“并应符合 TSG 21《固定式压力容器安全技术监察规程》”（是否属于监管范围由用户确认，程序不判定）；−0.02 MPa < p < 0.1 MPa → NB/T 47003.1-2022。没给设计压力时 `design_standard` 写“待填”。只引用标准号，不引用条款号；适用范围以原文为准 |
| R-SHEET-01 | 幅面缺省为 A1 横放。比例先在 GB/T 14690 优先系列里选能放下主视图的最大比例；放不下，或图面利用率低于 `rules.json` 的阈值时，允许用第二系列 1:15/1:25/1:30（`fit_scale` 加 `series` 参数，`geom/layout.py` 里已有 `SECOND_SCALES`）。仍然放不下就加长幅面或降一档，并给出提示 |

#### 4.4 尺寸基准与几个关键定义（写进设计说明，并放进第 14 节请用户确认是否符合本单位习惯）

- **立式**：高度基准取下封头与筒体之间的环焊缝，图上标“基准线”。**卧式**：轴向基准取左封头与筒体之间的环焊缝。R-LEN-01、尺寸链、管口定位都用同一个基准。
- 筒体管口：`axial_mm` 是基准到管口轴线的距离；`projection_mm` 是沿管口轴线，从法兰密封面到筒体外表面的距离；管口表里的“设备中心线至法兰面距离”= Do/2 + projection_mm，由代码计算。
- 封头管口：`radial_mm` 是设备轴线到管口轴线的距离；`projection_mm` 定义为法兰密封面到该端封头与筒体环焊缝的垂直距离 H（不用“到封头外表面”，因为偏心管口和椭圆面的交点不唯一）。

| `sheet.py` | `compose(spec, d)` | 选幅面比例 → 视图放进模型空间（1:1）→ 建布局「设备图」→ 图框 + 标题栏（`title_block_ops` 加 `template` 参数，新增 `titleblocks/hg_equipment.json`；`default_viewport_corners` 里写死的 40 改为读模板高度）→ 视口（主视图、方位图/左视图，各用标准比例并锁定）→ 表格和技术要求放在图纸空间 → 每个视口一套标注样式（`dimscale` = 比例分母） |

| `volume.py`（P1） | `full_volume`、`mass` | P0 时设计数据表的“全容积”“设备质量”写“待填（P1 计算）” |

**画法要求**（依据 HG/T 20668《化工设备设计文件编制规定》和机械制图国标中的简化画法；开发时逐条核对原文）：
1. **壁厚夸大只改图形，不改参数，也不改尺寸**：模型空间里壁厚按 `max(δ×s, 1.0 mm)/s` 向外夸大画（s 为比例，Di 保持不变），δ 的尺寸文字强制写参数值；外形尺寸、筒体长度等都用参数值作为文字，不用测量值；技术要求注明“壁厚夸大画出”。剖面涂黑的阈值以 GB/T 4457.5-2013 原文为准。
2. **管口旋转画法**：主视图里的管口按方位“旋转到投影面”画，方位角 0°~180° 的转到右侧，180°~360° 的转到左侧（以设计说明为准）；真实方位由管口方位图（立式）或左视图（卧式）表达。转到同一侧后同一高度投影重叠的，后一个改用局部视图表达，并给警告 `W_ROTATED_OVERLAP`。
3. 法兰按简化画法画（外形矩形 + 密封面线），不画螺栓；标准件（人孔、视镜、液位计）按简化外形画，明细栏写标准号。
4. 封头与筒体之间的环焊缝画细实线，基准线要标注；文字高度和图线由 `check.py` 检查，阈值引用 `cad/standards.py` 的常量。
5. 管口方位图：筒体外圆 + 十字中心线 + 0°/90°/180°/270° 标记 + 每个管口一条径向短线（标符号和角度）+ 支座位置；方位约定写在图旁。

#### 5.2 表格结构（以 HG/T 20668-2000 原文核对后写入 `templates/vessel_tables.json`）

- **管口表**：符号 | 公称尺寸 DN | 公称压力 PN | 连接标准 | 法兰型式 | 连接面形式 | 用途或名称 | 设备中心线（封头管口为基准线）至法兰面距离 | 备注（“按默认”“初选待校核”“补强待计算”等）。
- **明细栏**（自下而上填写）：件号 | 图号或标准号 | 名称 | 数量 | 材料 | 质量 kg（单件/总计）| 备注。P0 的质量格写“—”，备注写“P1 计算”。现有 `architectural.py` 的 `BOM_COLS` 没有质量列，不要直接套用。
- **设计数据表**（压力容器；非压力容器改用“技术特性表”）的行：设计、制造与检验标准；容器类别；工作压力；设计压力；工作温度；设计温度；介质；介质特性；主要受压元件材料；腐蚀裕量；焊接接头系数；热处理；无损检测；耐压试验（型式/压力）；泄漏试验；保温层厚度；全容积；充装系数；设计使用年限；基本风压/地震设防烈度；安全阀整定压力；设备质量。没有的项写“待填”。
- **技术要求**模板（只留待填槽位，不编数值）：① 设计、制造、检验标准（R-STD-01）；② 焊接接头型式除注明外按 HG/T 20583-2020，焊材待填；③ 无损检测方法、比例和合格级别待填；④ 耐压试验、泄漏试验的型式和压力待填；⑤ 管口方位以管口方位图（卧式为左视图）为准；⑥ 壁厚夸大画出（如适用）；⑦ 未核对数据声明（如适用）：“本图标准件尺寸部分未经核对，仅供方案阶段使用”；⑧ 固定最后一条：“本图未进行强度计算、开孔补强计算和支座校核，不得直接用于制造”。

#### 5.3 参数补丁与选择器

```json
{"op": "create", "spec": {"kind": "vertical_vessel", "shell": {"inner_diameter_mm": 1600, "length_mm": 2400, "thickness_mm": 8, "material": "Q345R"},
                          "nozzles": [{"dn": 500, "kind": "manhole", "purpose_text": "人孔"}, {"dn": 80, "purpose_text": "进料口"}],
                          "supports": [{"kind": "lug", "count": 4}]}}
{"op": "patch", "set": {"nozzles[purpose=进料口].orientation_deg": 90, "design.design_pressure_mpa": 1.0},
                "add": {"shell.length": 500},
                "upsert_nozzles": [{"dn": 50, "purpose_text": "放空口", "location": "top_head"}],
                "remove_nozzles": ["e"], "upsert_supports": [], "remove_supports": []}
```

- **选择器**：按符号 `nozzles[b]`，按用途 `nozzles[purpose=进料口]`，按位置 `nozzles[location=top_head]`，以及 `heads[top]`、`supports[0]`。选择器由代码确定性解析：匹配 0 个报 `NOT_FOUND`，匹配多个报 `AMBIGUOUS` 并附候选符号。这两种情况**引擎都直接转成反问**，不再重规划。路径必须在 `allowed_paths(kind)` 里，否则报 `BAD_PATH`，hint 列出可用路径。
- **用途受控词表** `data/nozzle_purposes.json`：每个规范名带一组同义词（进料口 ← 进料/进料管/入料口/进口；出料口 ← 出料/出口；放空口 ← 放空/排气口；排净口 ← 排污/排液；液位计口 ← 液位计/液面计……）。`apply_patch` 存规范名，原话存进 `purpose_text`；词表外的用途原样保存并给出警告。
- `add` 只用于相对改动（“加长/增加/减少”），增量必须是用户说的数。`shell.length` 是逻辑路径：加到用户给过的那个口径上（筒体长度或切线长），结果由代码计算。
- 用户给的值覆盖规则默认值。**规则默认值会随相关参数重新计算，用户给的值不会被规则覆盖**（例如改了设计压力后，默认 PN 重新取档，用户明确指定过的 PN 保持不动）。
- 引擎调用 `vessel_define` 时注入本轮的 `turn_id`（模型不写），用户值的来源记为 `user:<turn_id>`。

### 7. 设备图自检（`zhihui/cad/equipment/check.py`；`vessel_check` 和导出交付件前调用；`validate_general` 增加可选参数 `vessel=True`）

| E_MARK_DUP | 错误 | 管口符号重复 |

### 9.2 Few-shot

### 9.3 设备补丁护栏（`guards.py` 新增 `check_vessel_patch`，只用于 `vessel_define`）

现有的 `check_plan` 对设备补丁效果正好相反。实测中，模型编出的 方位 180°、径向 800（=1600/2）、PN16（=8×2）、直边 25（借自 DN25）都能通过（原因是 `guards.py:20` 的常量表和 `:43` 的倍数放行）；而“内径1.6米”写成 1600 反而被拦下。新护栏：
1. 数值必须与规范化后原话（含反问的回答）里的某个数**精确相等**，不用常量表，不放行倍数；带单位的写法（`{"value":1.6,"unit":"m"}`、`"600kPa"`）由 `apply_patch` 换算后再比对。
2. **可默认字段**用“字段→触发词”表判断（`orientation_deg`←方位/度/朝/转到；`projection_mm`←伸出/外伸；`pn`←PN/公称压力；`flange_type/facing`←SO/WN/RF/平焊/密封面；`heads.kind`←椭圆/碟形/半球/平盖/锥；`straight_flange_mm`←直边；`axial_mm/radial_mm`←距/离/高度为……）：值必须出现在触发词所在的分句里，否则护栏**确定性地剔除这个字段并给出警告** `E_DEFAULTABLE_FIELD`，不触发重规划。
3. **必问字段和照抄字段**里来源不明的数值，拦截并重规划；照抄的文本字段（材料、介质、标准）检查是否为原话的子串，或同义词表里的规范写法。
4. 管口符号只有在原话中出现时才能写。
5. 单测覆盖上面列出的全部探针（编造类全部被拦或被剔除，用户写法全部放行）。
