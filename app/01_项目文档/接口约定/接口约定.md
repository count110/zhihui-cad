# 智绘CAD 接口约定 v0.1（2026-10-13）

全员以本文件和同目录下自动导出的 JSON 为准。改接口的人负责：改代码 → `python -m zhihui.contracts` 重新导出 → 在群里说一声。

| 文件 | 内容 | 来源 |
|---|---|---|
| `tools.schema.json` | MCP 工具的输入 Schema：流程图工具（`profile: pfd`，24 个）+ 通用 CAD 函数（`profile: general`，54 个，带 `category`，见第 8 节） | 从 MCP Server 自动导出 |
| `cad_ir.schema.json` | CAD-IR 图纸数据模型（含通用图字段 `mode/layers/entities/blocks/layouts/…`） | 从 `zhihui/ir/models.py`、`zhihui/ir/general.py` 自动导出 |
| `symbols.json` | 12 种图元及端口 | 从 `zhihui/cad/symbols/*.json` 自动导出 |

---

## 1. 坐标与单位

- 模型空间单位一律为 **mm**；向右、向上为正。
- 图幅 A3（420×297）、A2、A1，默认比例 1:50。图框 = 图幅 × 比例（A3 1:50 → 21000×14850 mm）。
- 图元 JSON 里的尺寸是「图纸 mm」，原点在图元中心附近；加载时乘 `SYMBOL_SIZE`（1.25），出图时再乘 `drawing.unit`（= 比例 × 图幅相对 A3 的放大倍数）。图框、标题栏只乘比例。
- 图元 JSON 格式、出图规范（线宽、字体、位号栏、图框、标题栏）见 `03_CAD算法与图元库/README.md`。
- 设备坐标 `(x, y)` 是**图元原点**；`None` 表示还没布局。
- 管线 `path` 是正交折线，首点 = 起点端口，末点 = 终点端口。

## 2. CAD-IR 要点（详见 `cad_ir.schema.json`）

- 设备 `id`（E1…）在图内永久不变；位号 `tag`（P-101）可以改。工具参数里两者都能用。
- 连接 `id`（C5…）永久不变。端口引用写成 `位号.端口名`，如 `P-101.out`。
- `revision`：每次工具调用成功 +1，历史版本都留在 `data/drawings/<id>/revs/`。
- `base_revision`：改图时的基线版本。差异报告和误改检查都以它为准。
- `declared_impact`：改图工具声明的影响集。`validate_drawing` 检查影响集之外有没有变化。

## 3. MCP 工具（13 个，白名单）

所有工具返回**一行紧凑 JSON**：成功为 `{"ok": true, ...}`；失败为 `{"ok": false, "error_code", "message", "hint"}`，其中 `hint` 是写给大模型的一句修复提示。
**每个工具是一个事务**：失败不改变图纸；所有修改只作用于副本，原件永不覆写。

| 工具 | 主要输入 | 返回 | 用于 |
|---|---|---|---|
| create_drawing | title, paper_size, scale, template_id（高程布置图的其余参数见 4.1） | drawing_id、图元清单（含端口） | 生成 |
| place_equipment | drawing_id, **items[]**（symbol_id, tag, name, params） | 每台设备的端口列表 | 生成、修改 |
| connect_ports | drawing_id, **items[]**（from_port, to_port, line_type, medium）, remove[] | connection_ref 列表 | 生成、修改 |
| auto_layout | drawing_id, spacing, mode（auto/full/incremental）, paper_size | 坐标、排数、布线数、失败连接 | 生成、修改 |
| add_annotation | drawing_id, anchor_ref, text, style | annotation_ref | 生成、修改 |
| inspect_drawing | file_ref（或 drawing_id） | 新 drawing_id、设备/连接摘要、拓扑一致性、drawing_texts | 修改 |
| find_entities | drawing_id, query / tag / symbol_id / layer / text | 候选及匹配度，同分时带 `ambiguous` | 修改 |
| move_equipment | drawing_id, equipment_ref, dx, dy | 新旧坐标、重连的管线 | 修改 |
| edit_equipment | drawing_id, equipment_ref, new_tag / new_symbol_id / new_name / params / delete | 新旧映射、端口映射、受影响连接 | 修改 |
| validate_drawing | drawing_id, check_profile, expected_changes | passed、errors[]、warnings[]、stats | 生成、修改 |
| export_artifacts | drawing_id, formats | 文件 file_ref + sha256；改图时附带 diff | 生成、修改 |
| add_hatch | drawing_id, pattern, paper_spacing, angle, style, **pick**（{anchor, dx, dy} 或 {x, y}）/ **select**[], gap_tol | hatch_id、面积（m² / 图纸 mm²）、孤岛数、边界是否精确、预览 PNG | 生成、修改 |
| edit_hatch | drawing_id, hatch_ref, pattern / paper_spacing / angle / style / gap_tol / delete | 修改项、面积、是否失去关联 | 修改 |

和方案书 V3 相比的调整（都是为了少几轮调用、填补设计缺口）：
- `place_equipment` 和 `connect_ports` 改成**批量**：一次传全部设备 / 连接。10 台设备的图从约 27 轮降到 4–5 轮。
- `connect_ports` 增加 `remove`，用于断开或改接管线；端口可以只写位号，由工具自动选择空闲端口。
- `auto_layout` 增加 `mode=incremental`：改图时已有设备锁定不动，只给新设备找空位。
- `auto_layout` 增加 `paper_size`：超幅时由智能体决定是否换大图幅。

## 4. DXF 语义标签

| 对象 | 写法 |
|---|---|
| 设备 | 块参照 INSERT，块名 `ZH_<symbol_id>`；属性 TAG 可见（设备旁只注位号），NAME、SYMBOL、EID、PARAMS 不可见；XDATA(ZHIHUI) = `["equip", eid]` |
| 位号栏 | 图纸上方的位号、位号线、设备名称（TEXT / LINE，图层 TAG_ROW），XDATA = `["tag_row", eid]`；读回时忽略 |
| 管线 | LWPOLYLINE，图层 PIPE_PROCESS / PIPE_UTILITY / PIPE_AUX；XDATA(ZHIHUI) = `["conn", cid, from_eid, from_port, to_eid, to_port, line_type, medium]` |
| 箭头 | SOLID，XDATA = `["arrow", cid]` |
| 介质标注 | TEXT（图层 PIPE_TEXT），XDATA = `["conn_label", cid]` |
| 标注 | TEXT（图层 ANNO），XDATA = `["anno", aid, anchor]` |
| 填充 | HATCH（图层 HATCH，细线 0.18、颜色 8），XDATA = `["hatch", hid, anchor_ref, pick_rel, pattern, paper_spacing, angle, style, mode, boundary_refs, gap_tol, layer]`；读回时还原成 CAD-IR 的 Hatch。没有这个 XDATA 的填充（外来）只读 |
| 图纸级 | 根字典 `ZHIHUI` → XRECORD `META`：生成器版本、拓扑校验码、完整 CAD-IR JSON（按 200 字符分块） |

读回时**以实体为准**重建。设备在 CAD 里被挪动、管线没跟上，会列入 `stale_pipes` 并自动重新布线；没有 XDATA 的线按端点距离推断，列入 `inferred_connections`。这两种情况都会要求先让用户确认。

### 4.1 出图模板 water_elevation（给水处理 工艺流程及高程布置图，10.17 新增）

新增字段都有默认值，旧 JSON / DXF 照常读；默认值不写进 DXF 内嵌的 IR，`pfd_default` 的导出文件与之前逐字节一致。

| 位置 | 新增 |
|---|---|
| `create_drawing` | `template_id='water_elevation'`；`title_block`（unit_name、project、stage、discipline、drawing_name、drawing_no、scale_text、date、cert_no、sign_roles）、`notes[]`、`legend_codes[]`、`code_names{}`、`vscale`（图纸 mm / m），全部可选、只能来自用户 |
| `place_equipment` items | `params.elevations`（water / water_in / water_out / max_water / min_water / top / bottom / ground，单位 m）、`system`（子系统名）、`boxed`（虚线框） |
| `connect_ports` items | `code`（YS / QS / FX / CL / PAC / Q）、`spec`（如 DN200）；`code` 为 PAC/CL 或从投药设备出发、只写位号时自动接下游的 `dose` 口 |
| `add_annotation` | `anchor_ref='notes'`：追加一条说明（仅此模板） |
| CAD-IR | `Connection.code/spec`；`Annotation.style='elevation'`；`Drawing.title_block/notes/legend/legend_codes/code_names/systems/vscale/elev_frame` |

DXF：不画位号栏，块属性 TAG 不可见；管线在代号处断成几段，第一段带完整 XDATA（多 `code, spec` 两项），其余段 `["conn_part", cid, 序号]`，读回时拼成整条；
线旁半箭头为 LINE（`["arrow", cid]`）；高程数值 TEXT 的 XDATA 为 `["anno", aid, anchor, "elevation", x, y]`；名称、图例、标题、说明、子系统标题分别为
`name_label / legend / title / notes / system`，读回时不算图中自由文字。图层：`PIPE_YS` 等按代号分层（YS/QS 粗 0.7，其余 0.35）、`ELEV`、`GROUND`、`LEGEND`、`SYSTEM`、`FLOW_ARROW`。

## 5. Web API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/tasks` | 表单：`prompt`（必填）；`file`（.dxf，≤10 MB）或 `parent_id`（在上一个任务的结果上继续改） |
| GET | `/api/tasks/{id}?after=<事件id>` | 任务视图 + 增量事件（前端每 0.7 s 轮询一次） |
| POST | `/api/tasks/{id}/reply` | JSON `{"answer": "..."}`，回答反问 |
| POST | `/api/tasks/{id}/cancel` | 取消任务 |
| GET | `/api/files?ref=&exp=&sig=` | HMAC 签名下载，链接 1 小时内有效 |
| GET | `/api/health` | 健康检查 |

**状态机**：`QUEUED → PLANNING → RUNNING → VALIDATING (→ REPAIRING → …) → READY`，另有分支 `WAITING_CONFIRMATION / FAILED / CANCELLED`。

**事件**（`events[]`）：
- `status`：`{status, round?, errors?, reason?, question?}`
- `tool_call`：`{name, arguments, ok, summary, ms}`
- `assistant`：`{text}`
- `user`：`{text}`

**任务结果**（`result`）：`message, drawing_id, question, artifacts[{format, file_ref, url, bytes, sha256}], validation, diff, usage{tool_calls, prompt_tokens, completion_tokens, seconds, models}`

```jsonc

 "expected": {"equipment": [{"tag": "V-101", "symbol_id": "tank"}], "connections": [["V-101", "F-101"]]},
 "plan": {"title": "...", "equipment": [...], "connections": [...]}}      // plan 供离线脚本模式与 M/F 类生成基线图
// M 修改
{"id": "M001", "category": "M", "base_case": "G001", "prompt": "把 F-201 右移 800 mm",
 "expected": {"type": "move|retag|replace|add|delete", "target": "F-201", "dx": 800, "dy": 0},
 "steps": [...]}                                                           // steps 供离线脚本模式
// F 异常
{"id": "F001", "category": "F", "base_case": "G003" | "file": "corrupt|foreign", "inject_text": "...",
 "prompt": "...", "expected": {"outcome": ["WAITING_CONFIRMATION", "FAILED"], "must_keep": 3}}
```

## 8. 通用 CAD（`Drawing.mode == "general"`，2026-10-20 新增）

通用图和流程图并存：`mode` 默认 `pfd`，旧图 JSON 无损加载；新建通用图或上传普通 DXF 时为 `general`。详见《通用CAD能力_设计说明.md》，逐项完成度见《通用CAD能力_功能对照表.md》。

### 8.1 函数（54 个，`category` 即意图类别）

返回格式、事务、错误码风格与第 3 节一致：成功 `{"ok": true, created, modified, deleted, summary, data, warnings, defaults_used}`，失败 `{"ok": false, error_code, message, hint, …}`；**一次成功修改一个版本**；“安静”函数（视图、选择、绘图辅助开关、出图、坐标解析）不落版本。

| `2d_drafting`（5） | `draw_linear_primitives` `draw_complex_curves` `draw_polygons_and_meshes` `draw_circular_primitives` `create_hatch` |
| `precision_snap`（2） | `parse_coordinate_input` `resolve_osnap_point` |
| `view_select`（2） | `control_viewport_view` `select_entities` |
| `2d_editing`（9） | `replicate_entities` `transform_entities` `adjust_line_lengths` `modify_corners_and_breaks` `explode_compound_entities` `grip_edit_entity` `modify_entity_properties` `match_entity_properties` `erase_entities`（补充，提示词漏了“删除”） |

| `layout_plotting`（3） | `switch_model_and_layout_space` `manage_layout_viewports` `configure_plot_and_export` |

### 8.2 通用图新增错误码（节选）

| 代码 | 含义 / 修复提示 |
|---|---|
| `INVALID_ARGS` / `MISSING_ARG` | 参数字段、枚举或类型不对 / 缺必需值（缺数值要向用户确认，不要编造） |
| `REF_UNRESOLVED` | 变量引用解析不了（步骤没成功、字段不存在） |
| `LAYER_LOCKED` / `LAYER_FROZEN` / `LAYER_IS_CURRENT` / `LAYER_IN_USE` / `LAYER_PROTECTED` | 图层状态不允许；锁定图层会触发“要不要先解锁”的反问 |
| `AMBIGUOUS` / `NOT_FOUND` | 识别有多个候选（带 `candidates`）/ 没找到（带原因） |
| `NO_INTERSECTION` / `NO_SNAP_POINT` / `NO_SOLUTION` / `NO_TANGENT` / `PARALLEL` / `COLLINEAR` | 几何上无解 |
| `RADIUS_TOO_LARGE` / `OFFSET_TOO_LARGE` / `DEGENERATE` | 参数导致退化（倒角半径过大、偏移过大…） |
| `BOUNDARY_NOT_CLOSED` | 填充/边界不闭合，`gaps` 里有缺口位置 |
| `NONSTANDARD_SCALE` / `VIEWPORT_LOCKED` / `LAYOUT_EXISTS` | 布局与视口 |
| `OVER_CONSTRAINED` / `UNSOLVABLE` / `CONSTRAINT_VIOLATION` | 约束冲突或无解，`suspects` 列出可疑约束 |
| `DEVIATION_UNKNOWN` / `SIZE_UNKNOWN` / `KEYWAY_UNKNOWN` | 标准表里查不到，反问用户给数值 |
| `BOOLEAN_UNSUPPORTED` / `TAPER_UNSUPPORTED` / `UNSUPPORTED` | 超出实现范围（三维布尔：两个 z 向棱柱总是可以；其它实体需要可选依赖 manifold3d，没装报 `BOOLEAN_UNSUPPORTED` 并提示 `pip install manifold3d`） |
| `BOOLEAN_FAILED` / `EMPTY_RESULT` | 三维布尔：实体网格不是封闭流形（`open_edges`、`same_direction_edges`）/ 运算失败；结果为空（如交集没有重叠） |
| `STYLE_NOT_FOUND` / `BLOCK_NOT_FOUND` / `SYMBOL_NOT_FOUND` / `XREF_NOT_FOUND` / `ENTITY_NOT_FOUND` | 引用的对象不存在 |
| `CONFIRM_REQUIRED` | 一次处理超过 20 个对象，需要用户确认 |
| `NESTED_BATCH` / `NOT_ALLOWED_IN_BATCH` / `UNKNOWN_TOOL` | 批量使用不当 |
| `NOTHING_TO_UNDO` / `NOTHING_TO_REDO` | 撤销栈/重做栈为空 |
| `FILE_UNREADABLE` / `E_NO_ODA` / `DWG_XREF_UNSUPPORTED` / `E_FILE_REJECTED` | 文件读不了 / 没装 ODA / 不支持的文件 |
| `WRONG_MODE` | 在流程图上调用通用函数（或反过来） |
| `INTERNAL` | 未预期异常，图纸没有被修改 |

### 8.3 计划协议（Planner 输出，pydantic 严格校验）

```jsonc
{"thought": "", "intent_categories": ["2d_drafting"], "normalized_utterance": "",
 "workflow_steps": [
   {"step_id": "s1", "target_agent": "entity_recognition_agent", "depends_on": [], "action_summary": "识别大圆圆心",
    "payload": {"query": "大圆圆心", "need": ["entity_ids", "snap:center"]}},           // 或 {"tool": "<感知函数>", "args": {...}}
   {"step_id": "s2", "target_agent": "tool_execution_agent", "depends_on": ["s1"], "action_summary": "画小圆",
    "payload": {"tool": "draw_circular_primitives", "args": {"curve_type": "circle", "method": "center_diameter", "center": "$s1.points.primary", "diameter": 8}}}],
 "replan_after": null, "clarification_needed": false, "clarification": {"question": "", "options": [], "candidates": []}, "user_response_preview": ""}
```

变量引用：`$sN.created[i]`、`$sN.entity_ids[i]`、`$sN.points.<snap>|primary|[i]`、`$sN.boundary.outer|islands`、`$sN.data.<字段>`、批内 `$this[i].created[0]`、`$LAST_CREATED`、`$LAST_MODIFIED`、`$SELECTION`、`$LAST_POINT`。解析不了报 `REF_UNRESOLVED`。

## 9. 化工设备图（`Drawing.vessel`，2026-10-21 新增）

设备图仍是 `mode == "general"` 的图纸，多一个 `vessel: VesselSpec | None` 字段（见 `cad_ir.schema.json`）；`vessel` 不为空时前端进入“化工设备图”工作空间。详见《化工设备图_设计说明》《化工设备图_功能对照表》《化工设备图_数据表清单》。

### 9.1 函数（意图类别 `chem_equipment`，5 个；Schema 见 `tools.schema.json`）

| 函数 | 说明 |
|---|---|
| `vessel_define(op, spec?, set?, add?, upsert_nozzles?, remove_nozzles?, upsert_supports?, remove_supports?, renumber?, regenerate?, sheet?, scale?, confirmed?)` | 参数补丁 → 补默认 → 生成整张设备图；`turn_id` 由引擎注入 |
| `vessel_generate_drawing(views?, sheet?, scale?, export?)` | 参数不变时重排、另出「管口方位图」、导出 DXF/PDF/PNG/SVG（PDF/PNG 从布局「设备图」渲染） |
| `vessel_query(what, filter?)` | 只读 |
| `vessel_lookup_standard(table_id, keys)` | 只读，不需要图纸 |
| `vessel_check()` | 只读，第 7 节自检 |

路径写法：`shell.length_mm`、`design.design_pressure_mpa`、`heads.kind`（全部封头）/ `heads[top].kind`、`supports[0].count`、`drawing.sheet`；`add` 里用逻辑路径 `shell.length`。管口选择器：`nozzles[b]`、`nozzles[purpose=进料口]`、`nozzles[location=top_head]`、`nozzles[kind=manhole]`、`nozzles[dn=80]`，可用逗号组合。数值可写数、`{"value":1.6,"unit":"m"}` 或 `"600kPa"`。

### 9.2 错误码（新增）

`SPEC_INCOMPLETE`（hint 外另有 `pending=[{path,label,options}]`）、`STD_SIZE_NOT_FOUND`（带 `table_id`、`keys`、`coverage`）、`NOZZLE_NO_ROOM`、`SPEC_CONFLICT`、`AMBIGUOUS`（带 `candidates`、`options`）、`NOT_FOUND`、`INVALID_VALUE`、`NOT_SUPPORTED`、`HEAD_UNSUPPORTED`、`BAD_PATH`（带 `allowed`）、`BAD_UNIT`、`NO_VESSEL`、`CONFIRM_REQUIRED`、`E_VESSEL_CHECK`（导出交付件时自检有错误）。前 9 个由引擎直接转成反问（`question.items`），不调模型、不落版本。

自检码：`E_SPEC_PENDING E_NOZZLE_OVERLAP E_NOZZLE_OUT_OF_RANGE E_NOZZLE_ON_SEAM E_NOZZLE_SUPPORT_CLASH E_MARK_DUP E_TABLE_MISMATCH E_DIM_CHAIN E_VIEW_OVERLAP E_SCALE_NONSTANDARD E_TEXT_HEIGHT`；警告 `W_DEFAULT_USED W_UNVERIFIED_TABLE W_DESIGN_DATA_MISSING W_SUPPORT_NOT_CHECKED W_ROTATED_OVERLAP`；护栏 `E_INVENTED_VALUE`（拦截）、`E_DEFAULTABLE_FIELD`（剔除并警告）。

### 9.3 计划协议的变化

`clarification.items: [{path, label, options}]`（path 必须是可用路径，图种用 `drawing_type`）；`intent_categories` 可选值从注册表生成，含 `chem_equipment`。
